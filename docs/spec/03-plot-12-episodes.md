## 5. พล็อตภาคแรก

### ชื่อคดี

**The Wrong Number — ตัวเลขที่ไม่ควรอยู่ตรงนั้น**

### คำโปรย

แพลตฟอร์ม SIGNAL ถูกสร้างขึ้นเพื่อช่วยนักเรียนส่งปัญหาและช่วยโรงเรียนเลือกโครงการที่ควรแก้ก่อน แต่รายงานกลับจัดอันดับโครงการที่ไม่มีใครจำได้ว่าเสนอขึ้นมาเป็นอันดับหนึ่ง ข้อมูลจากบางโรงเรียนหายไป และจำนวนผู้สนับสนุนดูสูงกว่าจำนวนผู้ใช้จริง

### คำถามหลักของคดี

> ทำไม SIGNAL จึงจัดอันดับผิด และโครงการอันดับหนึ่งมาจากไหน?

### คำตอบของคดี (ผู้เขียน/ผู้พัฒนาต้องรู้; เกมเฉลยตามลำดับ)

ไม่มีผู้ร้ายคนเดียวที่แฮกระบบ ความผิดพลาดหลายชั้นทำให้รายงานเข้าใจผิด:

1. ทีมกิจกรรมใช้ข้อมูลทดสอบเก่าจากพื้นที่ sandbox ปะปนกับข้อมูลทดลองจริง
2. รหัสโรงเรียนไม่ได้อยู่ใน key ที่ใช้เชื่อมข้อมูล ทำให้ student ID ที่ซ้ำกันข้ามโรงเรียนถูกรวมเป็นคนเดียวหรือถูกนับผิด
3. KPI เดิมให้น้ำหนักจำนวนการกดสนับสนุนมากกว่าความรุนแรงและจำนวนผู้ได้รับผลกระทบ
4. แบบฟอร์มบางประเภทกรองหมวด “accessibility” ออก ทำให้รายงานของนักเรียนกลุ่มหนึ่งไม่แสดงบน dashboard
5. มีนักเรียนอาสาสมัครใช้บัญชีทดสอบร่วมเพื่อแจ้งเตือนความผิดปกติ แต่ไม่เปิดเผยตัวเพราะคิดว่าจะถูกกล่าวหาว่าก่อกวน

คดีจึงเป็นปริศนาเรื่อง data lineage, join key, metric design, missing data, usability, access control และการสื่อสาร ทีมต้องไม่กล่าวหาบุคคลจาก log หรือคะแนนเพียงอย่างเดียว

### วิธีคลี่คลาย

- ระบุแหล่งที่มาของข้อมูลและแยก sandbox ออกจากข้อมูลทดลอง
- เพิ่ม school ID และ source/version ให้ทุก record
- ทดสอบ join ด้วยข้อมูลตัวอย่างที่ควบคุมได้
- แสดงจำนวนผู้ใช้ที่ไม่ซ้ำและผลกระทบ ไม่ใช้ยอดกดอย่างเดียว
- ตรวจแบบฟอร์มกับนักเรียนหลายกลุ่ม รวมถึงผู้ใช้ที่ระบบเดิมเข้าถึงไม่ดี
- เปลี่ยนสิทธิ์และยกเลิกบัญชีทดสอบร่วม
- ขอให้นักเรียนอาสาสมัครยืนยันเหตุการณ์โดยสมัครใจ ไม่เปิดเผยชื่อโดยไม่จำเป็น
- นำเสนอระบบจัดลำดับปัญหาใหม่ที่โปร่งใส และให้คณะกรรมการมนุษย์พิจารณาร่วมกับข้อมูล

### การปิดคดี

ใน EP12 โรงเรียนแก้ผลจัดอันดับ ประกาศข้อจำกัดของข้อมูล ปรับกระบวนการรับรายงาน และตกลงแนวทางเก็บข้อมูลที่เคารพความเป็นส่วนตัว คณะกรรมการเลือกโครงการใหม่โดยอิงทั้งข้อมูลและเสียงจากนักเรียน คดี SIGNAL จบครบ ไม่มีผู้ต้องสงสัยลอยค้าง ส่วนทีม 2-A ตัดสินใจทำงานร่วมกันต่อในโครงการใหม่

### Beat sheet สำหรับผู้เขียน/ผู้พัฒนา

**EP1 — A Problem Without a Name**  
เปิดตัวโจทย์ของ Future School Project ที่สั้นและกว้างเกินไป; Chief รวมทีมที่ยังไม่สนิทกัน; Kuro เสนอสร้างระบบแจ้งปัญหา ส่วน Miyu ชี้ว่าทีมยังไม่รู้ปัญหาหรือผู้ใช้; ทีมตั้งแผนเก็บข้อมูล; ตอนท้าย Kuro กับ Miyu พบไฟล์ CSV ไม่มี source และโน้ตนิรนามว่า “The top score came from the wrong campus.” ทั้งคู่ตกลงเก็บไฟล์ไว้โดยไม่เปิดเผยต่อทีมก่อนตรวจสอบความปลอดภัยและแหล่งที่มา

**EP2 — The Cafeteria Queue**  
Miyu สัมภาษณ์นักเรียนโรงอาหารหลายช่วงเวลา; คนหนึ่งบอกว่าคิวช้า แต่การสังเกตพบว่าปัญหาจริงคือไม่รู้ว่าควรต่อแถวไหน; Kuro สร้างตัวจับเวลาทดลองที่ไม่เก็บชื่อ; Rei พบว่ารายงานเวลาเฉลี่ยของโรงเรียนขัดกับข้อมูลสังเกต; เบาะแสคือข้อมูลใน report มีช่วงเวลาที่โรงอาหารปิด

**EP3 — The Students We Missed**  
Lena พบว่านักเรียนปีหนึ่งและนักเรียนที่ใช้ screen reader แทบไม่ตอบแบบสอบถาม; Miyu ปรับคำถามสัมภาษณ์ให้ไม่ชี้นำ; Kuro ทำแบบฟอร์มบนมือถือ; Shion พบคำถามบังคับที่ทำให้บางคนส่งไม่ได้; ทีมเรียนรู้ว่าผลสำรวจไม่แทนเสียงของทุกคนและพบว่ารหัสโรงเรียนพันธมิตรไม่ถูกเก็บใน export

**EP4 — Two Schools, One ID**  
Rei แสดงตัวอย่าง record ที่นักเรียนจากสองโรงเรียนมี ID เหมือนกัน; Kuro ทดลอง join ตารางแบบใช้ student ID อย่างเดียวและสร้างการนับผิดซ้ำได้; Miyu ขอให้ทีมพันธมิตรยืนยันขั้นตอนสร้างข้อมูลโดยไม่กล่าวหา; ปริศนาย่อยจบว่า mapping key ไม่ครบ ไม่ใช่มีคนปลอมตัว

**EP5 — The Missing Category**  
นักเรียนแจ้งว่าแบบฟอร์มไม่มีตัวเลือกเรื่องการเข้าถึงอาคาร; Miyu เก็บ requirement จากผู้ใช้ที่ได้รับผลกระทบ; Kuro เพิ่มตัวเลือกใน prototype; Shion ทดสอบค่าอื่น/ช่องว่าง/การส่งซ้ำและพบ category ถูกซ่อนใน filter ของ dashboard; ฉากหลังเลิกเรียนสร้างความไว้ใจเล็ก ๆ ระหว่าง Kuro กับ Miyuจากการช่วยกันแก้ปัญหา

**EP6 — The Score That Went Viral**  
โครงการหนึ่งมีคะแนนพุ่งหลังแชร์ลิงก์ในชมรม; Rei แยก unique students ออกจากจำนวน clicks; Miyu สัมภาษณ์ผู้สนับสนุนและพบว่าหลายคนกดเล่นโดยไม่ได้อ่านรายละเอียด; Kuro กับ Chief จำลองคะแนนสองสูตร; ข้อค้นพบคือ popularity เป็น metric ที่ไม่เท่ากับ impact

**EP7 — A Test Account at Midnight**  
Shion ตรวจ log พบ test account ที่ถูกใช้หลังเลิกเรียน; ทีมทำ timeline ร่วมกับ IT โดยไม่เผยข้อมูลส่วนตัว; Kuro อธิบายว่าบัญชีร่วมทำให้ระบุตัวคนไม่ได้; Miyu เสนอถามอาสาสมัครอย่างเป็นกลาง; หลักฐานชี้ว่ามีการใช้บัญชีทดสอบ แต่ยังไม่พิสูจน์การเจาะระบบ

**EP10 — The Report Nobody Could Send**  
นักเรียนกลุ่มหนึ่งใช้ฟอร์มไม่ได้และบางคนไม่ต้องการให้ระบุตัว; ทีมทบทวน consent, data minimization และสิทธิ์เข้าถึง; Kuro อยากแก้ให้ทันกำหนด ส่วน Miyu ยืนยันว่าต้องมีทางเลือกที่ปลอดภัย; ทั้งคู่ตกลงใช้ anonymous mode ที่ไม่ถามข้อมูลเกินจำเป็นและทดสอบกับผู้ใช้ก่อน

**EP12 — A Decision for Students**

### รายละเอียดการคลี่คลายท้ายภาค

- ทีมแสดงให้เห็นว่าการรวมข้อมูลผิดเกิดจาก key ที่ไม่ครบและการใช้ test export ผิดชุด
- คะแนนพุ่งจาก KPI ที่นับการกดสนับสนุน ซึ่งกลุ่มนักเรียนบางกลุ่มเข้าถึงได้มากกว่า
- ปัญหาการส่งแบบฟอร์มทำให้กลุ่มผู้ใช้บางคนหายจากข้อมูล ไม่ใช่เพราะพวกเขาไม่มีปัญหา
- ผู้ส่งคำเตือนไม่ใช่คนร้าย เขาคือนักเรียนอาสาสมัครที่พบ test record และใช้บัญชีที่ไม่ควรแชร์
- โรงเรียนยืนยันว่าไม่มีข้อมูลส่วนบุคคลถูกเผยแพร่สู่สาธารณะในเรื่องนี้ แต่ยอมรับว่าการควบคุม test access และการบันทึก source ไม่ดีพอ
- การตัดสินใจใหม่ผ่านคณะกรรมการนักเรียนและครูร่วมกัน
