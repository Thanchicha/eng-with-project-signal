## 3. จักรวาลและกติกาเรื่อง

### ชื่อภาค

**Angels of Deceit: Project SIGNAL**

### ฉาก

โรงเรียนมัธยม CAGE และกิจกรรม Future School Project ซึ่งเป็นการแข่งขันนวัตกรรมระหว่างโรงเรียน ผู้เข้าร่วมเป็นนักเรียน ครู เจ้าหน้าที่โรงเรียน สภานักเรียน ชมรม และโรงเรียนพันธมิตร

โจทย์ที่ทีม 2-A ได้รับคือ:

> Use data to improve student life.

โจทย์นี้จงใจกว้างเกินไป ทีมจึงต้องค้นหาว่าปัญหาของนักเรียนคืออะไร ก่อนตัดสินใจว่าจะสร้างอะไร

### เส้นแบ่งจาก SS1

- เป็น Alternate Universe (AU) ไม่ใช่ภาคต่อของเหตุการณ์ SS1
- ยืมชื่อและแกนบุคลิกของ Kuro, Miyu, Lena, Shion และ Rei มาปรับใช้
- ไม่มี Project Eden, Subject 06, A.D. หรือปมครอบครัวจากเส้นเรื่องหลัก
- ไม่มีพลังเหนือธรรมชาติหรือความทรงจำถูกลบ
- สมาชิกทีมหลักเพิ่งมารู้จักกันและยังไม่มีความสัมพันธ์สนิทสนมก่อนเริ่มโปรเจกต์
- ทุกคนเป็นนักเรียน; ปัญหาและคดีเกิดในบริบทโรงเรียน
- โรงเรียนอื่นเป็นคู่แข่งหรือพาร์ทเนอร์ในกิจกรรมได้ แต่ไม่ขยายคดีไปสู่บริษัทหรือโลกนอกโรงเรียน
- คดีหลักของภาคแรกต้องปิดสมบูรณ์ใน EP12 ภาคใหม่ใช้คดีใหม่และอาจกล่าวถึงบทเรียนเก่าสั้น ๆ ได้

### โทน

School mystery, technology, teamwork, comedy และ romance เบา ๆ บรรยากาศมีความลึกลับ แต่ไม่กดดันหรือรุนแรงเกินวัย ปริศนาเกิดจากข้อมูล กระบวนการ และการตัดสินใจของคน ไม่ใช่การทำร้ายร่างกาย

## 4. ตัวละครหลักและหน้าที่ในทีม

Kuro และ Miyu ต้องมีบทที่มีผลต่อเรื่องใน **ทุกตอน** ไม่ใช่เพียงปรากฏตัวผ่านฉากสั้น ๆ ทุกตอนต้องให้ทั้งคู่ทำงานร่วมกัน ขัดแย้งกันอย่างมีเหตุผล หรือช่วยกันเปิดเบาะแส

### Kuro Kagami — Developer / Technical Lead

- สุขุม ระวังตัว ช่างสังเกต และสนใจระบบเบื้องหลัง
- แสดงความใส่ใจด้วยการลงมือแก้ปัญหา มากกว่าพูดปลอบ
- ถนัดตรวจโครงสร้างระบบ เขียน prototype เชื่อมข้อมูล และไล่บั๊ก
- จุดที่ต้องเรียนรู้: อย่ารีบสร้างก่อนเข้าใจผู้ใช้ และอย่าตัดสินใจแทนผู้ได้รับผลกระทบ
- ภาษาเป้าหมาย: อธิบายข้อจำกัดทางเทคนิค สถานะงาน บั๊ก และสิ่งที่ต้องการจากทีม
- ตัวอย่าง: “The prototype works, but it does not solve the main problem yet.”

### Miyu Luminous — Business Analyst

- ภายนอกสุภาพและเป็นที่รู้จักในโรงเรียน; ตัวจริงขี้เล่น เจ้าเล่ห์นิด ๆ และอ่านคนเก่ง
- ถนัดสัมภาษณ์ แยกความต้องการจากวิธีแก้ที่คนเสนอ และสรุป requirement
- จุดที่ต้องเรียนรู้: ฟังให้ครบก่อนสรุป และทำให้ requirement ตรวจสอบได้
- ภาษาเป้าหมาย: ถามปลายเปิด ขอรายละเอียด ยืนยันความเข้าใจ และเขียน acceptance criteria ง่าย ๆ
- ตัวอย่าง: “Could you walk me through what happens when you use the current system?”

### Airi Tachibana — Project Manager; ทุกคนเรียก “Chief”

- หัวหน้าห้องที่จัดระบบและรับผิดชอบสูง
- เพื่อนเรียก Chief จนติดปาก แม้เธอจะบอกให้เรียก Airi
- ดูเป้าหมาย ขอบเขต เวลา การแบ่งงาน การประชุม และการสื่อสารกับครู/คณะกรรมการ
- ไม่ใช่ผู้รู้ทุกเรื่อง; หน้าที่คือทำให้ผู้เชี่ยวชาญแลกข้อมูลและตัดสินใจทันเวลา
- ภาษาเป้าหมาย: จัดประชุม มอบหมายงาน ขอ update และสรุป next steps
- ตัวอย่าง: “Let’s agree on the problem before we divide the tasks.”

### Rei Amane — Data Analyst

- ให้ความสำคัญกับหลักฐาน ตัวเลข และการตรวจสอบที่มา
- ตรวจข้อมูลซ้ำ ค่าที่หายไป การแบ่งกลุ่ม นิยาม metric และสร้างสรุปหรือ dashboard
- จุดที่ต้องเรียนรู้: ตัวเลขมีบริบท และข้อสรุปต้องบอกข้อจำกัด
- ภาษาเป้าหมาย: อธิบายแนวโน้ม เปรียบเทียบกลุ่ม และบอกความไม่แน่นอน
- ตัวอย่าง: “The report shows more submissions, but we do not know whether more students took part.”

### Lena Kurosawa — UX Researcher / Partnership Coordinator

- เข้ากับคนง่าย รู้จักนักเรียนหลายกลุ่ม และช่วยให้ทีมเข้าถึงผู้ใช้จริง
- สัมภาษณ์ สังเกตการใช้งาน ทำ user journey และประสานโรงเรียนพันธมิตร
- จุดที่ต้องเรียนรู้: แยกคำชมจากหลักฐานการใช้งาน และจดสิ่งที่สังเกตอย่างเป็นระบบ
- ภาษาเป้าหมาย: ชวนคุย ขออนุญาตสังเกต และสรุป feedback
- ตัวอย่าง: “Would you mind showing me how you usually submit a report?”

### Shion Amane — QA / Risk Analyst

- เงียบ สุขุม และเห็นรายละเอียดที่คนอื่นข้ามไป
- ทดสอบกรณีปกติและกรณีขอบ (edge cases), ตรวจสิทธิ์/ความเป็นส่วนตัว และบันทึกความเสี่ยง
- จุดที่ต้องเรียนรู้: ยกประเด็นความเสี่ยงให้ทีมเข้าใจได้โดยไม่ทำให้ทุกคนหยุดเพราะความกลัว
- ภาษาเป้าหมาย: รายงานขั้นตอนทดสอบ ความเสี่ยง และสิ่งที่ยังไม่ยืนยัน
- ตัวอย่าง: “I found a case where one student can submit the same report twice.”

### Stakeholder ที่ปรากฏในเรื่อง

- นักเรียนผู้แจ้งปัญหาและนักเรียนที่ไม่เคยตอบแบบสอบถาม
- สภานักเรียนและชมรม
- ครูที่ดูแล Future School Project
- เจ้าหน้าที่ IT ของโรงเรียน
- ร้าน/หน่วยบริการในโรงเรียน เช่น โรงอาหารและห้องสมุด
- ทีมจากโรงเรียนพันธมิตรหรือคู่แข่ง
- คณะกรรมการนักเรียนที่จัดสรรงบประมาณ

ใช้คำว่า “ผู้ใช้” หรือ “นักเรียนผู้รับบริการ” ตามความเหมาะสม ไม่ทำให้ตัวละครวัยเรียนกลายเป็นพนักงานบริษัท
