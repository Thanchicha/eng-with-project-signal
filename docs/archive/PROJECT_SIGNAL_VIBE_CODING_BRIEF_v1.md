## 1. สรุปแนวคิด

Project SIGNAL คือเว็บเกมฝึกภาษาอังกฤษผ่านเรื่องลึกลับในโรงเรียน ผู้เล่นร่วมทีมกับ Kuro, Miyu และเพื่อนนักเรียนเพื่อค้นหาว่าทำไมระบบประกวดนวัตกรรมของโรงเรียนจึงจัดอันดับโครงการผิดพลาด ระหว่างสืบสวน ผู้เล่นฝึกอ่านบทสนทนา ใช้ประโยคภาษาอังกฤษที่จำเป็นต่อการทำงาน ตั้งคำถาม วิเคราะห์ข้อมูล และเลือกวิธีสื่อสารกับคนหลายบทบาท

เกมใช้ตัวละครและแรงดึงดูดจาก Angels of Deceit แต่เกิดในจักรวาลทางเลือกที่แยกจากเส้นเรื่อง SS1 โดยสิ้นเชิง ทุกคนเป็นนักเรียน ไม่มีเหตุการณ์เหนือธรรมชาติ และปริศนาหลักของภาคแรกคลี่คลายในโรงเรียนเมื่อจบตอนที่ 12

**คำอธิบายสั้นสำหรับนำเสนอ:**

> เว็บเกมฝึกภาษาอังกฤษสำหรับการทำงานเป็นทีม ผู้เล่นช่วย Kuro, Miyu และเพื่อน ๆ ไขปริศนาข้อมูลในโรงเรียน พร้อมฝึกถาม อธิบาย และตัดสินใจด้วยภาษาอังกฤษที่ใช้ได้จริง

### เสาหลักของประสบการณ์

1. **เรื่องนำการเรียน:** ผู้เล่นอยากรู้คดีต่อ จึงมีเหตุผลที่จะอ่านและโต้ตอบภาษาอังกฤษ
2. **ภาษาใช้ทำงานจริง:** ฝึกถาม requirement, ขอคำชี้แจง, รายงานปัญหา, อธิบายข้อมูล และสรุปข้อเสนอ
3. **คิดแบบทีมผลิตภัณฑ์:** ทุก role มีมุมมองและงานของตัวเอง แต่ต้องร่วมกันตัดสินใจ
4. **ผิดแล้วเรียนต่อได้:** คำตอบไม่ทำให้ติดทางตัน เกมบอกผลของการสื่อสารและให้ลองใหม่
5. **รักวัยเรียนแบบค่อยเป็นค่อยไป:** Kuro กับ Miyu เริ่มจากคนที่เพิ่งรู้จักกัน ความผูกพันเกิดจากการทำงานและการไว้ใจกัน

## 2. ผู้เล่นและเป้าหมายการเรียน

### ผู้เล่นหลัก

นักเรียนหรือนักศึกษาที่กำลังเตรียมตัวฝึกงาน โดยเฉพาะผู้สนใจ Business Analyst, Data Analyst, Product/Project Management, Software Development, UX, IT และ Cybersecurity แต่ยังไม่มั่นใจภาษาอังกฤษ

### เมื่อเล่น MVP จบ ผู้เล่นควรทำได้

- อ่านบทสนทนาง่ายระดับ A2–B1 และจับใจความหลักได้
- ถามเพื่อทำความเข้าใจปัญหาและ requirement
- ขอให้คู่สนทนาอธิบายหรือยกตัวอย่างเพิ่มอย่างสุภาพ
- ใช้แม่แบบประโยคแล้วแทนคำศัพท์เพื่อสร้างประโยคใหม่
- รายงานข้อสังเกตจากข้อมูลโดยไม่สรุปเกินหลักฐาน
- แยกปัญหา ผู้ใช้ ความต้องการ และแนวทางแก้ในระดับเบื้องต้น
- ฝึกพูดตามหรืออ่านออกเสียงบทสนทนาโดยไม่ถูกบังคับให้มีสำเนียงเหมือนเจ้าของภาษา

### ขอบเขตการเรียน

เกมนี้ช่วยฝึกภาษาและความเข้าใจงานระดับเริ่มต้น ไม่อ้างว่าแทนหลักสูตรวิชาชีพหรือประสบการณ์ทำงานจริง ทุกกรณีเป็นสถานการณ์จำลองเพื่อการเรียนรู้

## 3. จักรวาลและกติกาเรื่อง

### ชื่อภาค

**Angels of Deceit: Project SIGNAL**

### ฉาก

โรงเรียนมัธยม CAGE และกิจกรรม Future School Project ซึ่งเป็นการแข่งขันนวัตกรรมระหว่างโรงเรียน ผู้เข้าร่วมเป็นนักเรียน ครู เจ้าหน้าที่โรงเรียน สภานักเรียน ชมรม และโรงเรียนพันธมิตร

โจทย์ที่ทีม 2-A ได้รับคือ:

> Use data to improve student life.

โจทย์นี้จงใจกว้างเกินไป ทีมจึงต้องค้นหาว่าปัญหาของนักเรียนคืออะไร ก่อนตัดสินใจว่าจะสร้างอะไร

### เส้นแบ่งจาก SS1

- เป็น Alternate Universe (AU) ไม่ใช่ภาคต่อของเหตุการณ์ SS1
- ยืมชื่อและแกนบุคลิกของ Kuro, Miyu, Lena, Shion และ Rei มาปรับใช้
- ไม่มี Project Eden, Subject 06, A.D. หรือปมครอบครัวจากเส้นเรื่องหลัก
- ไม่มีพลังเหนือธรรมชาติหรือความทรงจำถูกลบ
- สมาชิกทีมหลักเพิ่งมารู้จักกันและยังไม่มีความสัมพันธ์สนิทสนมก่อนเริ่มโปรเจกต์
- ทุกคนเป็นนักเรียน; ปัญหาและคดีเกิดในบริบทโรงเรียน
- โรงเรียนอื่นเป็นคู่แข่งหรือพาร์ทเนอร์ในกิจกรรมได้ แต่ไม่ขยายคดีไปสู่บริษัทหรือโลกนอกโรงเรียน
- คดีหลักของภาคแรกต้องปิดสมบูรณ์ใน EP12 ภาคใหม่ใช้คดีใหม่และอาจกล่าวถึงบทเรียนเก่าสั้น ๆ ได้

### โทน

School mystery, technology, teamwork, comedy และ romance เบา ๆ บรรยากาศมีความลึกลับ แต่ไม่กดดันหรือรุนแรงเกินวัย ปริศนาเกิดจากข้อมูล กระบวนการ และการตัดสินใจของคน ไม่ใช่การทำร้ายร่างกาย

## 5. พล็อตภาคแรก

### ชื่อคดี

**The Wrong Number — ตัวเลขที่ไม่ควรอยู่ตรงนั้น**

### คำโปรย

แพลตฟอร์ม SIGNAL ถูกสร้างขึ้นเพื่อช่วยนักเรียนส่งปัญหาและช่วยโรงเรียนเลือกโครงการที่ควรแก้ก่อน แต่รายงานกลับจัดอันดับโครงการที่ไม่มีใครจำได้ว่าเสนอขึ้นมาเป็นอันดับหนึ่ง ข้อมูลจากบางโรงเรียนหายไป และจำนวนผู้สนับสนุนดูสูงกว่าจำนวนผู้ใช้จริง

### คำถามหลักของคดี

> ทำไม SIGNAL จึงจัดอันดับผิด และโครงการอันดับหนึ่งมาจากไหน?

### คำตอบของคดี (ผู้เขียน/ผู้พัฒนาต้องรู้; เกมเฉลยตามลำดับ)

ไม่มีผู้ร้ายคนเดียวที่แฮกระบบ ความผิดพลาดหลายชั้นทำให้รายงานเข้าใจผิด:

1. ทีมกิจกรรมใช้ข้อมูลทดสอบเก่าจากพื้นที่ sandbox ปะปนกับข้อมูลทดลองจริง
2. รหัสโรงเรียนไม่ได้อยู่ใน key ที่ใช้เชื่อมข้อมูล ทำให้ student ID ที่ซ้ำกันข้ามโรงเรียนถูกรวมเป็นคนเดียวหรือถูกนับผิด
3. KPI เดิมให้น้ำหนักจำนวนการกดสนับสนุนมากกว่าความรุนแรงและจำนวนผู้ได้รับผลกระทบ
4. แบบฟอร์มบางประเภทกรองหมวด “accessibility” ออก ทำให้รายงานของนักเรียนกลุ่มหนึ่งไม่แสดงบน dashboard
5. มีนักเรียนอาสาสมัครใช้บัญชีทดสอบร่วมเพื่อแจ้งเตือนความผิดปกติ แต่ไม่เปิดเผยตัวเพราะคิดว่าจะถูกกล่าวหาว่าก่อกวน

คดีจึงเป็นปริศนาเรื่อง data lineage, join key, metric design, missing data, usability, access control และการสื่อสาร ทีมต้องไม่กล่าวหาบุคคลจาก log หรือคะแนนเพียงอย่างเดียว

### วิธีคลี่คลาย

- ระบุแหล่งที่มาของข้อมูลและแยก sandbox ออกจากข้อมูลทดลอง
- เพิ่ม school ID และ source/version ให้ทุก record
- ทดสอบ join ด้วยข้อมูลตัวอย่างที่ควบคุมได้
- แสดงจำนวนผู้ใช้ที่ไม่ซ้ำและผลกระทบ ไม่ใช้ยอดกดอย่างเดียว
- ตรวจแบบฟอร์มกับนักเรียนหลายกลุ่ม รวมถึงผู้ใช้ที่ระบบเดิมเข้าถึงไม่ดี
- เปลี่ยนสิทธิ์และยกเลิกบัญชีทดสอบร่วม
- ขอให้นักเรียนอาสาสมัครยืนยันเหตุการณ์โดยสมัครใจ ไม่เปิดเผยชื่อโดยไม่จำเป็น
- นำเสนอระบบจัดลำดับปัญหาใหม่ที่โปร่งใส และให้คณะกรรมการมนุษย์พิจารณาร่วมกับข้อมูล

### การปิดคดี

### เนื้อหาพร้อมเล่น: Episode 1

ส่วนนี้เป็น reference content สำหรับสร้าง vertical slice; UI สามารถแสดงฉากทีละบรรทัดและแทรก interaction ตาม scene ID ได้

#### Before Reading

**สถานการณ์:** CAGE School เข้าร่วมการแข่งขันนวัตกรรมระหว่างโรงเรียน ทีม 2-A ต้องใช้ข้อมูลช่วยปรับปรุงชีวิตนักเรียน แต่โจทย์ยังไม่บอกว่าควรแก้ปัญหาอะไร

**เป้าหมาย:** เข้าใจโจทย์, ถามว่าใครคือผู้ใช้, และไม่รีบสร้างวิธีแก้ก่อนรู้ปัญหา

**คำศัพท์:** project (โครงการ), goal (เป้าหมาย), problem (ปัญหา), solution (วิธีแก้), requirement (ข้อกำหนด/ความต้องการ), stakeholder (ผู้เกี่ยวข้อง), user (ผู้ใช้), deadline (กำหนดส่ง), assumption (ข้อสันนิษฐาน), evidence (หลักฐาน), scope (ขอบเขต), source (แหล่งที่มา)

#### Scene 1 — The Brief

บรรทัดเรื่อง:

- Narration: “At 7:55 on Monday, a message appeared on every classroom screen.”
- Screen: “FUTURE SCHOOL PROJECT — Use data to improve student life.”
- Student: “Can we build a robot that does our homework?”
- Chief: “We have six weeks. First, we need to understand the task.”
- Kuro: “That is not a complete brief. It does not define the users or the result.”
- Miyu: “Then we should ask what problem the school wants us to solve.”

**Interaction:** What should the team clarify first?

- A: “Who are the users, and what problem do they have?” — feedback: ช่วยกำหนดผู้ใช้และปัญหาก่อนคิด solution; skill tag: problem-framing
- B: “Which programming language should we use?” — feedback: เป็นคำถามเทคนิคที่อาจจำเป็นภายหลัง แต่ยังเร็วไปก่อนรู้ว่ากำลังสร้างอะไร; skill tag: solution-first
- C: “Can we start building today?” — feedback: แสดงความกระตือรือร้น แต่ยังไม่มี requirement หรือ evidence; skill tag: planning

#### Scene 2 — Meet the Team

บรรทัดเรื่อง:

- Chief: “I’m Airi Tachibana, but everyone calls me Chief. I’ll manage the project.”
- Lena: “I can talk to students and arrange interviews.”
- Rei: “I can check what data the school already has.”
- Shion: “I’ll look for risks and cases we may miss.”
- Kuro: “I can inspect the current system and build a prototype.”
- Miyu: “I’ll find out what students actually need.”
- Kuro: “You already know what they need?”
- Miyu: “No. That’s why I need to ask them.”
- Chief: “Good. No one owns the whole answer. We’ll share what we learn.”

**Interaction:** The player chooses one useful PM question:

- “What is our deadline?” — reveals six-week plan; feedback about schedule
- “Who approves the final project?” — reveals teacher and student committee; feedback about decision stakeholders
- “Can we do every idea on the board?” — feedback: ช่วยเปิดประเด็น scope; ชวนถามต่อว่าจะจัดลำดับอย่างไร

#### Scene 3 — Problem or Solution?

บทสนทนา:

- Kuro: “We can build a reporting app.”
- Miyu: “What problem will it solve?”
- Kuro: “Students can report problems.”
- Miyu: “Who will read the reports? What will they do next?”
- Kuro: “We can decide that later.”
- Miyu: “If we decide later, we may build the wrong thing.”
- Kuro: “A prototype can help people react to something real.”
- Chief: “Both points are useful. We’ll learn about the problem and test a small prototype later.”

**Interaction:** Select the best next step:

- A: Interview students about a recent problem — feedback: เก็บ evidence จากประสบการณ์จริง; preferred next scene
- B: Build every feature Kuro can think of — feedback: เสี่ยง scope ใหญ่และยังไม่รู้ผู้ใช้
- C: Ask the teacher to choose a problem for students — feedback: ครูเป็น stakeholder แต่ไม่ควรใช้แทนเสียงผู้ใช้ทั้งหมด

#### Scene 4 — The Board and the First Clue

บทสนทนา:

- Rei: “The school has old reports about Wi-Fi, cafeteria lines, and missing announcements.”
- Shion: “The reports do not include every student group.”
- Lena: “I can help us speak with students from different classes.”
- Miyu: “Let’s ask about the last time the problem happened, not only what they prefer.”
- Kuro: “I found a file in the project folder. It has no source or owner.”
- Miyu: “Do we know if students agreed to share this data?”
- Kuro: “No. We should not use it yet.”
- Screen note: “The top score came from the wrong campus.”
- Miyu: “Is that a warning or a joke?”
- Kuro: “We don’t know. First, we check the file safely.”
- Chief: “Tomorrow we bring evidence, not guesses.”

**Interaction:** What should the team do with the file?

- A: Record where it was found and ask IT to confirm its source — feedback: รักษา evidence และขอผู้ดูแลระบบตรวจที่มา
- B: Publish it to the team chat so everyone can inspect it — feedback: แชร์ข้อมูลที่ไม่ทราบที่มา/สิทธิ์อาจสร้างความเสี่ยง
- C: Delete it immediately — feedback: ป้องกันการเปิดดูโดยไม่จำเป็นได้ แต่ทำให้เสียหลักฐาน; ควรจำกัดการเข้าถึงและแจ้ง IT

**Episode end:** ทีมเริ่มแผนสัมภาษณ์นักเรียนและเก็บเบาะแสเรื่อง campus ID โดยไม่มีใครถูกกล่าวหา

#### Analyst Note

- ข้อมูลไฟล์ไม่มี source จึงยังใช้สรุปหรือจัดอันดับไม่ได้
- ข้อความ “wrong campus” เป็น lead ที่ต้องตรวจ ไม่ใช่ข้อพิสูจน์ว่าโรงเรียนใดทำผิด
- Miyu แยก problem discovery ออกจาก solution design
- Kuro แสดงความรับผิดชอบด้วยการไม่ import ไฟล์ที่ไม่ทราบที่มา
- Chief จัดงานให้เดินต่อได้โดยไม่ต้องมีคำตอบทันที

#### Business & Data Lesson

ใช้กรอบ **User → Problem → Evidence → Success** ก่อนเลือก Solution:

- ใครกำลังเจอปัญหา?
- ปัญหาเกิดขึ้นเมื่อไรและอย่างไร?
- มีหลักฐานอะไรสนับสนุน?
- จะรู้ได้อย่างไรว่าดีขึ้น?

#### Sentence Patterns และ Drills

1. **We need to + verb** — We need to understand the problem.  
   แทนคำ: interview students / check the source / define the goal
2. **We don’t know whether + clause** — We don’t know whether the data is correct.  
   แทนคำ: the file is safe / students need this feature / the report is complete
3. **Before we + action, we should + action** — Before we use the file, we should check its source.  
   แทนคำ: build the app / talk to users; share the report / ask the data owner

ให้ผู้เล่นสร้าง 3–5 ประโยคด้วย pattern เหล่านี้และมี Show Example/Hint ได้

#### Speak Like an Intern

สถานการณ์: ผู้จัดการมอบหมายให้ทำ dashboard แต่ยังไม่ได้อธิบายผู้ใช้หรือการตัดสินใจ

- Manager: “Please create a dashboard for student problems.”
- Intern: “Could I ask a few questions about the requirements?”
- Manager: “Of course.”
- Intern: “Who will use the dashboard?”
- Manager: “The student committee and teachers.”
- Intern: “What decisions do they need to make?”
- Manager: “They need to choose which problem to address first.”
- Intern: “Let me check if I understand. We need to show the impact of each problem, not only the number of reports.”
- Manager: “Exactly.”

MVP: ให้กดฟังด้วย browser speech synthesis ได้ถ้ามีเสียง หรือให้ผู้เล่นอ่านตามเอง; การไม่มีเสียงต้องไม่ขัดขวางการเล่น

#### Mini Case

| ปัญหาที่ถูกรายงาน                     | จำนวนรายงาน |
| ------------------------------------- | ----------: |
| Slow Wi-Fi                            |          45 |
| Long cafeteria lines                  |          30 |
| Missing announcements                 |          15 |
| No wheelchair access to one classroom |           6 |
| Other                                 |           4 |

ผู้บริหารบอกว่า “Slow Wi-Fi has the most reports, so it must be our first priority.”

ให้ผู้เล่นตอบเป็นภาษาอังกฤษ:

- What else should we ask?
- Do we know how the students were selected?
- Does the number of reports show the severity of the problem?
- Who is affected by the access issue?

แม่แบบช่วยตอบ:

- “The data shows that ****\_\_****.”
- “However, we don’t know whether ****\_\_****.”
- “Before we decide, we should ****\_\_****.”

ตัวอย่างคำตอบที่ยอมรับ: “The data shows that Wi-Fi received the most reports. However, we don’t know how many students were affected by each problem. Before we decide, we should compare both impact and severity.”

#### Episode Recap

- ทีมได้โจทย์และกำหนดวิธีเริ่มค้นหาปัญหา
- ยังไม่ตัดสินใจสร้างแอปจนกว่าจะรู้ความต้องการ
- พบไฟล์ไม่มีแหล่งที่มาและเบาะแสเรื่อง wrong campus
- คำศัพท์ทบทวน: problem, requirement, stakeholder, evidence, source, scope
- รูปประโยคทบทวน: We need to… / We don’t know whether… / Before we…, we should…

### รายละเอียดการคลี่คลายท้ายภาค

- ทีมแสดงให้เห็นว่าการรวมข้อมูลผิดเกิดจาก key ที่ไม่ครบและการใช้ test export ผิดชุด

## 7. วงจรการเล่น

### วงจรหนึ่งฉาก

1. ผู้เล่นเห็นบริบทภาษาไทยสั้น ๆ และเป้าหมายฉาก
2. อ่านบทสนทนาภาษาอังกฤษระดับ A2–B1
3. เปิดคำศัพท์หรือวลีเฉพาะที่ต้องการ
4. เลือกคำตอบ พิมพ์ตอบ หรือเรียงคำ ตามชนิดกิจกรรม
5. รับ feedback ภาษาไทย: ความหมาย, น้ำเสียง, จุดที่สื่อสารได้ดี, รูปประโยคที่นำไปใช้ต่อได้
6. เห็นผลต่อภารกิจหรือบทสนทนา
7. ได้รับสรุปความรู้และบันทึกคำศัพท์

### โครงสร้างหนึ่งตอน

1. **Before Reading:** สถานการณ์ภาษาไทย, เป้าหมาย, คำศัพท์ 8–12 คำ
2. **Story:** นิยายภาษาอังกฤษ 4–6 ฉาก ประมาณ 500–800 คำในเวอร์ชันเต็ม; MVP ใช้ 3–4 ฉาก
3. **Inside the Analyst’s Mind:** เหตุผลของการถาม/วิเคราะห์และสิ่งที่ยังสรุปไม่ได้
4. **Business & Data Lesson:** หนึ่งแนวคิดพร้อมตัวอย่างในเรื่อง
5. **Sentence Patterns:** แม่แบบภาษาอังกฤษ 3 แบบ พร้อมวิธีแทนคำ
6. **Substitution Drill:** ฝึกเปลี่ยนคำหรือเรียงประโยค 3–5 ข้อ
7. **Write by Yourself:** เขียนประโยค 3–5 ข้อ; MVP แสดงคำแนะนำตามกฎ/ตัวอย่าง ไม่จำเป็นต้องใช้ AI
8. **Speak Like an Intern:** บทสนทนาฝึกพูด; MVP ใช้ปุ่มฟัง/อ่านออกเสียงหรือ shadowing โดยไม่บังคับ microphone
9. **Mini Case:** ตาราง/สถานการณ์สั้น ให้ตั้งคำถามและสรุปเป็นภาษาอังกฤษ
10. **Episode Recap:** สรุปคดี ความรู้ศัพท์ และภารกิจถัดไป

### การตัดสินใจและผลลัพธ์

- ให้ผู้เล่นได้เลือกคำตอบ 2–3 ทางในจุดสำคัญ
- แต่ละตัวเลือกสื่อถึงแนวทางต่างกัน เช่น ถามเพื่อเข้าใจ, รีบเสนอวิธีแก้, หรือขอหลักฐาน
- ผลของคำตอบปรับ feedback, trust/communication indicator, บทสนทนาสั้น หรือหลักฐานที่ได้
- เส้นเรื่องหลักมาบรรจบกันเพื่อควบคุม scope; ไม่สร้าง 12 ตอนที่แตกเป็นคนละเกม
- ไม่มี Game Over จากความผิดภาษา และไม่มีการล็อกเนื้อเรื่องเพราะตอบผิด
- ถ้าคำตอบสุภาพแต่ยังไม่ครบ ให้บอกว่ายังขาดข้อมูลอะไรและให้โอกาสถามต่อ

### คะแนน/ความคืบหน้า

ใช้ตัวชี้วัดเพื่อสะท้อนทักษะ ไม่ใช้จัดอันดับความเก่งของผู้เล่น:

- **Clear Communication:** สื่อความหมายและขอ clarification
- **Evidence Thinking:** ระบุหลักฐานและข้อจำกัด
- **Teamwork:** รับฟังและส่งต่อข้อมูลให้ทีม
- **Vocabulary Notebook:** คำที่พบ/ฝึกแล้ว/ควรทบทวน
- **Episode Progress:** ฉากที่ผ่านและบทที่ปลดล็อก

แสดง progress bar หรือ badge แบบเป็นมิตร ไม่ใช้พลังชีวิตที่หมดแล้วแพ้คดี

## 8. หลักการสอนภาษา

### ระดับภาษา

- Story ใช้ประโยคสั้นถึงกลาง คำศัพท์ที่บริบทช่วยเดาได้ และไวยากรณ์ไม่เกิน B1
- ศัพท์เทคนิคใหม่ตอนละไม่เกิน 8–12 คำ; คำซ้ำสำคัญให้กลับมาเจอในตอนต่อไป
- คำแปลไทยช่วยเริ่มต้น แต่ไม่แสดงแทนทุกคำโดยอัตโนมัติ ผู้เล่นกดเปิดได้
- เริ่มจาก Recognition (อ่าน/เลือก) ไป Guided Production (เติม/แทนคำ) แล้ว Free Production (เขียน/พูดเอง)

### Feedback สำหรับคำตอบ

Feedback ของทุกโจทย์ควรประกอบด้วย:

1. **You communicated:** เจตนาที่ผู้เล่นสื่อได้
2. **A natural option:** ตัวอย่างประโยคที่เป็นธรรมชาติ
3. **Why it works:** เหตุผลด้านน้ำเสียงหรือบริบทงาน
4. **Try a pattern:** แม่แบบที่ผู้เล่นนำไปใช้ในประโยคอื่นได้

อย่าบอกเพียงถูก/ผิด อย่าหักคะแนนเพราะสำเนียง และเมื่อมีคำตอบที่ถูกความหมายหลายแบบให้ยอมรับหลายรูปแบบ

### ตัวอย่าง sentence pattern สำหรับ EP1

**We need to + verb**  
We need to understand the problem.  
เปลี่ยนได้: interview the users / check the data / define the goal

**We don’t know whether + clause**  
We don’t know whether the data is correct.

**Before we + action, we should + action**  
Before we build the app, we should talk to the users.

## 9. หน้าจอและประสบการณ์ผู้ใช้

### A. Home / Episode Map

- แสดงชื่อ Project SIGNAL และปุ่ม Continue / Start Episode 1
- แสดงแผนที่ 12 ตอน โดยตอนที่ 1 เล่นได้ ตอนที่ 2–12 แสดง locked/preview
- มี Vocabulary Notebook, Progress และ Settings
- มีคำอธิบายเป้าหมายเรียนภาษาและระดับ A2–B1 สั้น ๆ

### B. Episode Intro

- ชื่อตอน, สรุปสถานการณ์ภาษาไทย 2–4 บรรทัด
- เป้าหมายบทและ role ที่ได้เรียนรู้
- รายการคำศัพท์สำคัญ
- ปุ่ม Begin Episode

### C. Story Scene

- ตัวละครและชื่อผู้พูดชัดเจน
- กล่องบทสนทนาภาษาอังกฤษอ่านได้ง่าย; ปุ่มเปิดคำแปลไทย
- แตะ/คลิกศัพท์เพื่อดูความหมาย ตัวอย่าง และออกเสียง (ถ้ามีเสียง)
- ตัวเลือกตอบแสดงเป็นประโยคที่ผู้เล่นอาจพูดจริง ไม่ใช่ข้อสอบ grammar ล้วน
- Quest panel แสดง objective ปัจจุบัน เช่น “Find out who will use the report.”
- Mobile: จัดเป็นแนวตั้ง, ปุ่มใหญ่, ไม่ต้องเลื่อนแนวนอน

### D. Learning Pause / Analyst Note

- แสดงสิ่งที่ตัวละครรู้, สิ่งที่ยังเป็น assumption, คำถามถัดไป
- ไม่เปิดเผยเฉลยปริศนาก่อนถึงจังหวะเรื่อง

### E. Exercise Panel

- แสดง pattern, ตัวอย่าง, ช่องเติมคำ/พิมพ์, ปุ่ม Show Hint และ Check Answer
- เปิดเฉลยตัวอย่างได้โดยไม่ทำให้เสีย progress
- ปุ่ม Try Again ใช้ได้เสมอ

### F. Mini Case

- แสดงตารางข้อมูลขนาดเล็กหรือกราฟง่าย ๆ พร้อมคำถาม
- ผู้เล่นเลือกสิ่งที่ต้องถามเพิ่มและเขียนสรุปสั้น ๆ
- คำตอบตัวอย่างแสดงหลังผู้เล่นลองตอบแล้ว

### G. Episode Complete

- สรุปว่าทีมค้นพบอะไร
- แสดงศัพท์/แม่แบบที่ฝึก
- แสดงทักษะที่ได้ใช้โดยไม่ตีตราว่าเก่งหรืออ่อน
- ปุ่มทบทวน, เล่นฉากสำคัญซ้ำ, กลับแผนที่

### ทิศทางภาพ

- บรรยากาศโรงเรียนเทคโนโลยีลึกลับแบบเป็นมิตร: navy/teal เป็นสีหลัก, warm cream สำหรับพื้นที่อ่าน, coral หรือ amber สำหรับจุดเน้น
- ใช้พื้นที่ว่างและตัวอักษรอ่านง่ายเป็นหลัก
- ภาพตัวละครใช้ placeholder avatar แบบวงกลม/ภาพประกอบการ์ดได้; MVP ไม่ต้องสร้างภาพ AI แยกครบทุก pose
- ใช้ motion เล็กน้อยเฉพาะเปลี่ยนฉาก/เปิดคำศัพท์ และเคารพ prefers-reduced-motion
- สีไม่ใช่สัญญาณเพียงอย่างเดียว; สถานะต้องมี label หรือ icon ด้วย

- ใช้ AI เป็นผู้ช่วยอธิบายคำตอบอิสระ ไม่ใช่ผู้ตัดสินใจเนื้อเรื่อง
- ให้คำตอบเป็นมิตรและไม่ลงโทษสำเนียง
- ใช้ข้อมูลจำลองในโจทย์; ห้ามส่งข้อมูลส่วนตัวนักเรียนจริง
- เมื่อ API ใช้ไม่ได้ แสดง feedback ที่เตรียมไว้และเกมยังเล่นต่อได้
- ไม่เก็บ audio หรือคำตอบผู้เล่นนานเกินจำเป็น; MVP ไม่อัปโหลดเสียง

## 13. แนวทางเทคนิคสำหรับ AI Coding Tool

### Stack ที่แนะนำสำหรับ MVP

- React + TypeScript + Vite
- CSS modules หรือ plain CSS ที่มี design tokens; เลือกวิธีเดียวให้สม่ำเสมอ
- React Router ใช้ได้ถ้าจำเป็น; ถ้า flow ยังสั้น ใช้ state/router แบบง่าย
- ไม่มี backend ในรอบแรก
- localStorage สำหรับ progress
- เนื้อเรื่องเก็บใน `src/content/` เป็น JSON/TypeScript
- ใช้ SVG/CSS/emoji แบบควบคุมได้สำหรับ placeholder avatar; อย่าพึ่ง image API

ถ้ามี starter repo หรือ stack ที่กำหนดไว้แล้ว ให้รักษาของเดิมและปรับเอกสารนี้ให้เข้ากับมัน แทนการแทนที่โครงสร้างทั้งหมด

### หลักการ component

## 14. เกณฑ์รับมอบ MVP

- ผู้เล่นเปิดเว็บแล้วเริ่ม Episode 1 ได้โดยไม่ต้องสมัครบัญชีหรือใส่ API key
- เล่นตั้งแต่ Before Reading จน Episode Recap ได้ครบ
- Kuro และ Miyu มีบทสนทนาและการกระทำที่จำเป็นต่อเนื้อหาในทุกฉากหลักของ EP1
- ผู้เล่นเปิด/ปิดคำแปลและเปิดคำศัพท์ตามต้องการได้
- ตัวเลือกแต่ละข้อมี feedback ภาษาไทยที่อธิบายบริบท ไม่ใช่แค่ correct/incorrect
- ฝึก sentence pattern อย่างน้อย 3 แบบ และพิมพ์คำตอบได้
- Mini Case แสดงข้อมูลให้ดูและตอบได้โดยไม่ต้องใช้ AI
- เมื่อ refresh หน้า ความคืบหน้าและคำศัพท์ยังอยู่ใน browser
- ตอน 2–12 แสดงชื่อ เรื่องย่อ บทบาทและแนวคิดที่จะเรียน พร้อมสถานะ locked
- หน้าจอมือถือไม่มีการเลื่อนแนวนอน; ปุ่มหลักอ่านและกดได้ง่าย
- ใช้งานด้วย keyboard ได้ และองค์ประกอบ interactive มี label ชัดเจน
- ปริศนาหลักถูกอธิบายเป็นข้อมูลทดสอบปะปน + key การ join ไม่ครบ + KPI/การเข้าถึงที่ผิดพลาด และไม่เฉลยว่าเป็นการแฮกโดยไม่มีหลักฐาน

## 16. ลำดับทำงานหลังได้เว็บ MVP

1. ตรวจ flow ว่าเล่น Episode 1 จบได้จริงบนมือถือและ desktop

3. ปรับระดับคำศัพท์ จังหวะเรื่อง ความยาวฉาก และ feedback จากการทดลอง
4. เติม Episode 2–3 เพื่อพิสูจน์ว่าโครงสร้าง content เพิ่มตอนใหม่ได้ง่าย
5. ค่อยตัดสินใจเพิ่ม AI free response หรือเสียง จากหลักฐานว่าช่วยผู้เรียนจริง
